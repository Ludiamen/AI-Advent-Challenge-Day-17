# Результаты Дня 17 — первый инструмент MCP

Что доказывается: свой MCP-сервер построен вокруг чужого HTTP-API, его
инструменты зарегистрированы и описаны, агент их вызывает — руками, по решению
модели и по подтверждённой заявке, — а результат попадает в ответ и в саму
чужую систему.

Прогон: `python check_tools.py --в RESULTS.md`. Мок-трекер (`tracker_api.py`)
скрипт поднимает сам на свободном порту; модель — `ds-flash`.

## Как читать

| Часть | Что проверяется | Чем доказывается |
|---|---|---|
| 1 | инструмент зарегистрирован | сервер поднимается как настоящий MCP-сервер (stdio), отдаёт `tools/list`, список сверяется с объявленным в коде; читающие помечены `readOnlyHint`, меняющие — нет; без `TRACKER_WRITE=1` меняющих нет вовсе |
| 2 | входные параметры описаны | каждая `inputSchema` — корректная JSON Schema типа object, у каждого параметра есть описание, обязательные объявлены, выход за границы отклоняется, а «../../etc/passwd» вместо ключа задачи отклоняется до запроса к API |
| 3 | результат возвращается | ответ инструмента сверяется с ответом самого API, запрошенным **независимо**, своим httpx-запросом мимо MCP: ключи задач, счётчик `X-Total-Count`, поля задачи, комментарии, доступные статусы |
| 4 | агент вызывает и использует | живой вопрос модели: она сама зовёт инструменты, вызовы записаны в журнал памяти, а в ответе появляются ключи задач и сроки, которых в промпте не было |
| 5 | изменение только с подтверждения | модель просит комментарий — вызова нет, есть заявка; подтверждение исполняет её, и комментарий виден в самом API; отклонённая заявка не меняет ничего |
| 6 | сбои названы | нет задачи, выдуманный ключ, недопустимый переход, трекер не отвечает, токен не принят |
| 7 | цена | во сколько токенов обходится список инструментов и насколько дороже запрос с ними |

Сверка с самим API — главный довод части 3. «Инструмент что-то вернул» — ещё не
доказательство: обёртка могла потерять поля, перепутать фильтр или показать
кэш. Независимый запрос к тому же API, сделанный мимо MCP, такую ошибку поймал
бы.

## Что из этого следует

**Сервер вокруг API — это работа с чужими состояниями, а не с данными.** Из
семи проверенных случаев сбоя пять приходят не от нашего кода: 401 (токен), 403
(организация), 404 (нет задачи), 422 (недопустимый переход), 429 (частые
запросы). Каждый переведён в предложение, которое модель может показать
человеку, вместо безликого «Error executing tool». Ради этого обёртка и нужна.

**Список инструментов совпал с объявленным в коде, а результат — с ответом API.**
Первое доказывает, что регистрация работает и сервер не отдаёт лишнего; второе —
что возврат результата не выдумка обёртки: те же ключи задач, тот же счётчик из
заголовка `X-Total-Count`, те же комментарии и те же доступные статусы приходят
и напрямую, мимо MCP.

**Выжимка экономит на порядок больше, чем кажется.** На списке из восьми задач
ответ API — 7 839 символов, выжимка — 2 777: на 65% меньше, и это в каждом
запросе, где список оказался в переписке. Служебных полей (`statusStartTime`,
`updatedBy`, `cloudUid`, `version`) в ней нет вовсе.

**Модель пользуется инструментами разумно.** На вопрос «что в работе и что
горит» она сделала пять-шесть вызовов: сначала список очередей, потом задачи по
фильтру, потом подробности отдельных задач — и в ответе появились ключи `MIG-2`,
`MIG-3`, `MIG-5` со сроками и исполнителями. На вопрос про векторные тайлы,
заданный в той же сессии с подключёнными инструментами, вызовов не было вовсе.

**Изменение не произошло без человека.** Просьба «добавь комментарий к MIG-7»
не вызвала `add_comment`: появилась заявка, а в самом трекере число
комментариев не изменилось. После `--подтвердить` комментарий появился — это
проверено прямым запросом к API, а не ответом агента. Отклонённая заявка не
изменила ничего, и повторно исполнить закрытую заявку нельзя.

**Цена видна и измерена.** Пять инструментов — это ≈ 1 278 токенов схемы в
каждом запросе. Вопрос с инструментами стоил 6 985 входных токенов против
3 069 у вопроса без них. Разница больше цены схемы: в запрос уходят ещё и
ответы инструментов, и так на каждом круге. Это и есть материал для сравнения
«MCP против скилла + CLI» в конце недели.

браузерного прогона исходники не трогать. Второй прогон нашёл ошибку уже в
самом проверочном скрипте — заявку он ждал в переписке, а она появляется
карточкой справа.

### Что нашли прогоны показа

- **Аргументы заявки печатались как `[object Object]`**, если среди них был не
  только текст. Теперь объект печатается JSON’ом — человек видит, что именно
  уйдёт в чужую систему.
- **Причина отказа приходит отдельной строкой ответа**, а не внутри строки
  вызова «↳». Проверка сцены сначала смотрела только на последний узел вызова и
  не находила текста, хотя он был на экране; теперь сцена смотрит всю переписку.
- **Панель MCP шире окна, и `scrollIntoView` уводил страницу вбок** — в кадре
  пропадала левая половина переписки. Нашлось разбором кадра готовой записи: в
  логах такого не видно. Теперь прокрутка идёт только по вертикали.

берёт окно браузера, записи не попадают в репозиторий), ворота стенда по

четыре потока разом получают список без повторов.

Сети эти тесты не трогают: мок-API поднимается как WSGI-приложение внутри
процесса, а настоящее соединение MCP идёт со своим сервером по stdio. Тесты
Дня 16 (54) и Дней 11–15 (283) остались без изменений — кроме двух, где
изменились ожидания самого дня: список серверов в `mcp-servers.json` и заголовок
страницы.
